# Биллинг: таблицы решений и описания тестов по ТЗ

Документ построен **только по тексту `docs/billing/tz.md`**. Исходный код, тесты, другие документы и история git не использовались. Единственное исключение — раздел 4.0 «Актуальность на 18.11.2026»: он сверяет вопросы Части 4 с текущим ТЗ и с фактическим поведением кода. Там, где ТЗ молчит, клетка помечена «ТЗ не отвечает», а рекомендация вынесена в Часть 4. Сведения о поведении ЮKassa и HTTP, которых в ТЗ нет, помечены «(пров.)» — они взяты из публичной документации провайдера и общих знаний, а не из ТЗ, и перед использованием их стоит перепроверить.

## Как читать

- **Часть 1** — «вызов × класс ответа»: одна строка на каждый класс ответа внешней системы или входящего вебхука. Вызов указан в заголовке подраздела.
- **Часть 2** — «состояние × событие»: строки — события, столбцы — состояния сущности. В каждой клетке её ID, статус и исход.
- **Часть 3** — описания тестов (дано / когда / тогда) и список свойств-инвариантов. В столбце «Клетки» перечислены все клетки, которые тест покрывает. Если один и тот же факт описан клеткой Части 1 и клеткой Части 2, их покрывает один тест; тест с несколькими клетками одной строки матрицы — параметризованный, исходное состояние для каждой клетки дано отдельно.
- **Часть 4** — пробелы и противоречия ТЗ, отсортированные по тяжести последствий. Ссылки вида `П-07` ведут туда.

Статусы клеток:

| Метка | Значение |
| --- | --- |
| `[О]` | определено ТЗ: исход прямо записан в указанном пункте |
| `[В]` | выводится из ТЗ косвенно: в клетке объяснено, из чего |
| `[Н]` | ТЗ не отвечает: исход не записан и однозначно не выводится |
| `[×]` | невозможно: сочетание состояния и события не может возникнуть (только Часть 2) |

Сокращения: «сигнал» — сигнал в мониторинг (запись в GlitchTip и `ERROR`-лог, `6.4`); «НИ» — неизвестный исход (инв. 10); «ТВ» — состояние задачи «Требует вмешательства» (`requires_intervention`); «инв. N» — инвариант N из раздела `3.4`; `T` — конец оплаченного периода.
