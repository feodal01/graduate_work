# Сценарий 1. Покупка подписки «Премиум» (ТЗ 9.2, шаги 1–2)

| Время | Что происходит |
| --- | --- |
| 00:00 | **Сценарий 1.** Пользователь без подписки покупает «Премиум» за 299 ₽ и сразу получает доступ к фильмам-новинкам. Проверяем TASK-1, TASK-5 и TASK-6. |
| 00:06 | **Шаг 1.1 · Экран входа (Э1).** Неавторизованного пользователя /billing/ перенаправляет на вход. Логин и пароль проверяет сервис Auth. |
| 00:14 | **Шаг 1.2 · «Моя подписка» (Э2).** Статус «Нет подписки», платежей пока нет, доступна кнопка «Оформить за 299 ₽». |
| 00:18 | **Шаг 1.3 · Новинка недоступна.** Просим у movies-api фильм-новинку с токеном пользователя. Auth не находит роль subscriber и запрещает просмотр. |
| 00:26 | **Шаг 2.1 · Двойное нажатие «Оформить».** Пользователь нетерпеливо нажимает кнопку дважды подряд — браузер отправляет на сервер два запроса покупки. |
| 00:40 | **Шаг 2.2 · Редирект на ЮKassa, платёж один.** Оба запроса получили один и тот же платёж: в БД его охраняет уникальный индекс «один pending на пользователя», а в ЮKassa ушёл один Idempotence-Key. |
| 00:49 | **Шаг 2.3 · Пользователь передумал и закрыл вкладку.** Не оплатив, он закрывает страницу ЮKassa и позже снова открывает личный кабинет. |
| 00:52 | **Шаг 2.4 · Незавершённая покупка в кабинете.** Статус «Ожидает оплаты», в истории — платёж в ожидании. Кнопка «Продолжить оплату» продолжит этот же платёж, а не создаст новый. |
| 01:04 | **Шаг 2.5 · Та же страница оплаты.** Пользователь снова на ЮKassa, и это тот же заказ — повторного списания не будет. Данные карты вводятся только у ЮKassa, Billing их не видит. |
| 01:15 | **Шаг 2.6 · Тестовая карта.** Mastercard 5555 5555 5555 4444 без 3-D Secure из списка тестовых карт ЮKassa; срок — любая будущая дата, CVC — любой. |
| 01:35 | **Шаг 2.7 · ЮKassa приняла оплату.** Деньги списаны в тестовом магазине. Теперь Billing должен узнать об этом и провести платёж у себя. |
| 01:41 | **Шаг 2.8 · «Результат оплаты» (Э3).** Пользователь вернулся на сайт. Экран читает статус только из нашей БД и обновляется сам, пока идёт проверка. |
| 01:48 | **Шаг 2.9 · Сигнал вебхука.** В продакшене ЮKassa сама присылает вебхук. До локального стенда он из интернета не доходит, поэтому отправляем его скриптом. Телу вебхука Billing не верит: берёт только id и перепроверяет платёж через GET в ЮKassa. |
| 01:53 | **Шаг 2.10 · Платёж проведён.** Billing сверил сумму, валюту и наш UUID в metadata, создал подписку и в той же транзакции поставил задачи: выдать доступ в Auth и отправить письма. |
| 02:02 | **Шаг 2.11 · Новинка доступна.** Тот же запрос фильма теперь проходит: Auth получил роль subscriber со сроком до конца подписки. |
| 02:11 | **Шаг 2.12 · «Моя подписка» после оплаты.** Статус «Активна до …» в часовом поясе пользователя, платёж 299 ₽ — «Оплачен». |
| 02:18 | **Шаг 2.13 · Письмо об оплате.** Notifications отправил письмо «Подписка „Премиум“ оплачена» (Mailpit перехватывает почту стенда). Адрес и имя Billing не хранит — письмо собрано по user_id. |
| 02:25 | **Шаг 2.14 · Письмо об окончании запланировано.** Последняя строка — отложенное письмо об окончании подписки на дату ends_at. При возврате оно будет отменено (сценарий 2). |
| 02:35 | **Шаг 2.15 · Повторная покупка запрещена.** Кнопки покупки в кабинете больше нет, а прямой запрос к API при активной подписке получает понятный отказ — второго списания не будет. |
| 02:44 | **Итог сценария 1.** Оплата через настоящий тестовый магазин ЮKassa, двойного списания нет, доступ к новинкам открыт, письмо пришло, письмо об окончании запланировано. |
