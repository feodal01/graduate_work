# UGC Events API

FastAPI-сервис принимает пакеты действий зрителя и публикует их в Kafka. Access JWT проверяется локально. Auth на каждый запрос не вызывается.

## Запуск в едином проекте

Выполните команды из корня репозитория:

```bash
cp .env.example .env
docker compose up -d --build
```

| Ресурс | Внешний URL |
| --- | --- |
| Swagger UI | `http://localhost/ugc/docs` |
| OpenAPI JSON | `http://localhost/ugc/openapi.json` |
| Health | `http://localhost/ugc/health` |
| События | `http://localhost/api/v1/ugc/events` |
| Kafka UI | `http://localhost:8080` |

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/v1/ugc/events` | Пакет действий зрителя в топик `ugc.events` |
| `GET` | `/api/v1/health/` | Состояние Kafka и Redis |

`POST` требует `Authorization: Bearer` с access JWT. `user_id` берётся из claim `sub`.

## Время события

`occurred_at` — время события на клиенте; часовой пояс обязателен.
`received_at` — серверное время UTC, которое API фиксирует один раз для всего пакета.
Допустимое окно по умолчанию:

```text
received_at − 7 суток ≤ occurred_at ≤ received_at + 5 минут
```

Обе границы включены. Смещения часового пояса сравниваются как моменты времени;
API сохраняет переданный `occurred_at` без автоматического исправления.
Окно позволяет отправить накопленные за семь суток события после восстановления связи.

API проверяет все события до пользовательского лимитера и публикации. Если время хотя бы
одного события выходит за окно, весь пакет получает `422`: Kafka и счётчик пакетов
не изменяются. `detail` содержит ошибки с `loc: ["body", "events", индекс, "occurred_at"]`;
индекс начинается с нуля. В `ctx` указаны общее `received_at` и ограничения в секундах.
Для принятого пакета то же `received_at` записывается во все конверты Kafka.

В корневом `.env` настройки — `UGC_EVENTS_MAX_AGE_SECONDS=604800` и
`UGC_EVENTS_MAX_FUTURE_SKEW_SECONDS=300`. Compose передаёт их одновременно API и ETL.
Для отдельных процессов имена — `EVENTS_MAX_AGE_SECONDS` и
`EVENTS_MAX_FUTURE_SKEW_SECONDS` в сервисных `.env`; значения должны совпадать у API и ETL.
Максимальный возраст должен быть положительным, отклонение в будущее может быть нулевым.

## Ограничение частоты приёма

Token bucket — счётчик разрешённых пакетов, который постепенно пополняется.
После проверки подписи access JWT, схемы и времени событий API расходует одну единицу
счётчика по `user_id`.
По умолчанию разрешён всплеск из 10 пакетов, затем счётчик пополняется со скоростью
60 пакетов за 60 секунд. Новый JWT того же пользователя не создаёт новый счётчик.
В каждом пакете по-прежнему не более 100 событий.

Счётчики хранятся в отдельном `ugc-events-redis`. Lua-скрипт атомарно проверяет
и обновляет счётчик по времени Redis, поэтому параллельные процессы API делят
один лимит. Неактивные ключи удаляются по TTL, состояние сохраняется через AOF.
Параметры `.env`: `UGC_EVENTS_RATE_LIMIT_RATE`, `UGC_EVENTS_RATE_LIMIT_WINDOW_SECONDS`
и `UGC_EVENTS_RATE_LIMIT_CAPACITY`. Все значения должны быть положительными.

До проверки JWT Nginx ограничивает запросы по IP: 20 запросов в секунду и
20 дополнительных запросов во всплеске. Используется отдельная зона `events_per_ip`.
Оба уровня возвращают `429` с `Retry-After` в секундах. Отклонённый пакет не
публикуется в Kafka.

Fail-open — при недоступном хранилище лимитов API продолжает приём событий.
Ошибка соединения или таймаут Redis записывается в warning с `request_id`;
пакет проходит обычные проверки и публикуется в Kafka. Лимит Nginx по IP сохраняется.
Ошибки Lua-скрипта не скрываются. Повторы запросов Redis отключены, circuit breaker нет.
После восстановления Redis пользовательский лимит применяется к следующим запросам.

При недоступном Redis и исправной Kafka health возвращает `200`:
`status: degraded`, `redis: unavailable`.
Если Kafka недоступна, приём и health возвращают `503`.
В Compose Redis — необязательная зависимость: API не ждёт его успешного healthcheck.

## Проверки

Тестам нужен отдельный Redis; они используют уникальные пространства ключей
и удаляют только свои данные. В CI Redis запускается автоматически.
Для локального Redis на порту 16379:

```bash
REDIS_PORT=16379 uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run mypy
```

Живая проверка из корня репозитория:

```bash
docker compose exec -T ugc-events python < tests/load/events_rate_limit.py
```

Скрипт создаёт тестовые события с уникальным `X-Request-Id`, проверяет лимит
с разными JWT одного пользователя, независимость другого пользователя,
совпадение записей Kafka с принятыми пакетами и лимит Nginx по IP.
Для точной проверки ёмкости серия должна завершиться до пополнения счётчика;
иначе скрипт завершается с ошибкой и сообщает, что результат неубедителен.
