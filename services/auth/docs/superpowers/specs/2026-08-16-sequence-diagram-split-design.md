# Разделение sequence-диаграмм сервиса авторизации

## Причина

`sequence-roles.puml` объединяет механизм RBAC-кэша, управление ролями и
проверку доступа к фильмам. Итоговый PNG достигает предельной высоты и
обрезается. Кроме того, несколько самостоятельных процессов трудно читать как
одну последовательность.

## Новая структура

### `sequence-authentication.puml`

Это новое имя существующего `sequence.puml`. Диаграмма продолжает описывать:

1. регистрацию;
2. вход;
3. обновление токенов;
4. изменение логина или пароля;
5. историю входов;
6. выход.

Содержимое этой диаграммы не меняется, кроме её технического имени и
заголовка. Существующий PNG также переименовывается и перерисовывается.

### `sequence-roles.puml`

Файл сохраняет имя и содержит только механизм RBAC-кэша:

1. чтение пользовательского снимка;
2. изменение прав одного пользователя через его маркер блокировки;
3. изменение общих ролевых правил через общий маркер блокировки;
4. создание нового снимка при следующей проверке прав.

### `sequence-role-management.puml`

Новая диаграмма содержит пользовательские сценарии управления ролями:

1. просмотр и создание ролей;
2. изменение и удаление роли;
3. назначение роли пользователю;
4. отзыв роли у пользователя.

Полный механизм проверки и обновления кэша здесь не повторяется. В нужных
местах диаграмма ссылается на `sequence-roles.puml`.

### `sequence-film-permission.puml`

Новая диаграмма содержит проверку доступа к фильму через
`POST /permissions/check`: проверку служебного ключа, применение политики по
возрасту фильма, обработку анонимного пользователя и проверку права
`films.early_access:read`.

Полный механизм RBAC-кэша не повторяется. Диаграмма ссылается на
`sequence-roles.puml`.

## PNG

Для каждого `.puml` создаётся одноимённый `.png`:

- `sequence-authentication.png`;
- `sequence-roles.png`;
- `sequence-role-management.png`;
- `sequence-film-permission.png`.

Старые `sequence.puml` и `sequence.png` после переименования отсутствуют.

## Проверка

1. `plantuml -checkonly docs/c4/*.puml` завершается без ошибок.
2. Все четыре PNG успешно создаются и имеют высоту меньше 4096 пикселей.
3. В новых диаграммах нет потерянных сценариев из исходных файлов.
4. `git diff --check` не находит ошибок оформления.
